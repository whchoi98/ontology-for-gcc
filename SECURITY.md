# Security Policy — ontology-gcc 1.0.0

This PoC handles **synthetic data only**. No real customer PII is committed to git.
Cognito demo passwords are not for production use. Please report security issues to
**security@whchoi.net** (PGP optional — contact for key).

## Plan 1–5 Security Decisions (Consolidated)

### Network & VPC

- **ADR 0001 — Retail VPC import**: GCC stack imports the existing
  `ontology-for-retail` VPC. East-west traffic and NACLs are governed by retail's
  baseline; GCC defines its own service-to-service security groups but does not
  add new subnets or route tables.
- **ADR 0002 — Domain deferred deployment**: First-pass deploy uses
  `*.cloudfront.net` so DNS provisioning never blocks the demo. ACM + custom
  domain wiring is documented in `docs/runbooks/02-add-custom-domain.md` with
  a rollback procedure.
- **CloudFront → ALB origin auth**: A constant-time-compared origin token
  (Secrets Manager) is required on every origin request, preventing direct
  ALB scrapes.

### Identity & Authentication

- **Cognito User Pool** with self-signup disabled, password policy enforced
  (min 8 chars, mixed case + digits + symbols).
- **Plan 5 Lambda@Edge JWT verification (Task 5.5.1)** —
  `infra-cdk/lambda-edge-auth/index.js` performs RS256 signature verification
  against the Cognito JWKS endpoint with a **10-minute TTL cache**. Built-in
  Node 20 `crypto.createPublicKey({format:'jwk'})` avoids the third-party
  `jwk-to-pem` dependency (smaller attack surface, faster cold start).
- Public paths (`/auth/*`, `/healthz`) bypass the edge auth function.
- All other paths return **302 → /auth/login** on missing/invalid/expired
  tokens — no implicit auth bypass.

### Data & Secrets

- **raw_data PII policy**: `raw_data/` is gitignored and stored only in a
  KMS-encrypted S3 bucket (`ontology-gcc-dev-raw-docs-*`). Production
  migration would require a dedicated anonymization pipeline (out of scope
  for this PoC).
- **Synthetic data only** in graph: every Customer / FuelTransaction /
  Coupon / etc. node is generated by `data/synthetic/*.py` based on raw_data
  column schemas — never the actual values. `data_depth` and `source` tags
  let the UI badge each node's provenance (real / synthetic / external).
- **External API keys**: Plan 2 KMA (기상청) and Plan 5 opinet keys live in
  AWS Secrets Manager (`ontology-gcc-dev/kma-api-key` and
  `ontology-gcc-dev/opinet-api-key`) — never in git, never in env files.
- **ADR 0005 — KMA API cache strategy**: 6-hour TTL JSON cache reduces
  external API hits by ~95% and shields the demo from KMA outages.

### IAM & Bulk Loader

- **ADR 0003 — Bulk Loader IAM prep**: Neptune Bulk Loader assumes a
  dedicated `BulkLoaderRole` with read access *only* to the synthetic data
  S3 prefix; no cross-bucket grants. The role's trust policy is scoped to the
  Neptune service principal.

### LLM Guardrails

- **Bedrock Guardrails** (Plan 3) — input + output filters with 4 topics:
  IPConfidential / CompetitorDisparagement / RegulationViolation /
  HazardousChemical. Violations are surfaced to the user via SSE log events
  and accumulated in the **Plan 5 ops_metrics buffer** for the operations
  console.
- **Tool sandboxing** (ADR 0006) — the agent only dispatches to a closed
  registry of 10 tool specs (`api/services/agent.py:TOOL_SPECS`). No
  arbitrary shell or code execution paths from user input.
- **Code Interpreter** runs in AgentCore's Firecracker sandbox — chart
  rendering uses NanumGothic fonts, no network egress allowed.

### Persona & Authorization

- **ADR 0007 — Persona registry as SSOT**: 5 부서 페르소나 (`marketing`,
  `strategy`, `data-ai`, `crm`, `retail-ops`) live in
  `api/services/persona.py:PERSONA_REGISTRY` — every router and system
  prompt looks up this single source of truth. UI persona switching never
  bypasses server-side persona resolution.

### Audit & Observability

- **agent.py trace ring buffer** (200 entries) and **ops_metrics
  guardrail buffer** (200 entries) are both in-process and reset on
  pod restart. For production-grade audit, ship to CloudWatch Logs with
  the existing observability stack. The current ops console
  (`/api/ops/live/{ingest,memory,eval,trace,guardrail}`) is for demo
  visibility, not regulatory audit.

## Known Caveats

- This PoC's network isolation depends entirely on retail's VPC posture.
  Production deployments should split into a dedicated VPC with strict
  east-west SG rules.
- Lambda@Edge JWKS cache uses in-memory state — across many cold starts the
  cache hit rate drops, slightly increasing the per-cold-start cost.
- Cognito demo passwords (`!234Qwer`) are intentionally weak for demo
  reproducibility. Rotate immediately for any non-demo deployment.
